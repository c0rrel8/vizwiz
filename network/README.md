# Network Diagram

A force-directed network showing nodes and edges with four layout
algorithms. **Raw Vega** (`.vg.json`) — the `force` transform is a
physics simulation with no Vega-Lite equivalent. Provider must be set to
**Vega** before pasting in Deneb.

## Features

- **Dual data mode**: `hierarchy` (reuses field parameter model —
  nodes from 3-level hierarchy, edges from parent-child relationships) or
  `edgelist` (Source/Target columns, each row is an edge).
- **Four layouts**: `force` (force-directed simulation), `circular`
  (nodes on a ring), `grid` (nodes in a grid), `hierarchical` (tree
  layout — hierarchy mode only, falls back to force in edge-list mode).
- **Force presets**: `compact`, `balanced`, `spread` — each sets link
  distance, repulsion, and link strength. Individual overrides available.
- **Directed/undirected toggle** with arrowheads on directed edges.
- **Draggable nodes** (experimental) — click and drag to reposition;
  the simulation re-settles around the pinned node.
- **Node sizing**: three modes — `fixed` (uniform radius), `metric`
  (scaled by Measure A), `degree` (scaled by connection count).
- **Edge weight channels**: three independent toggles — `thickness`,
  `opacity`, `color` (sequential). Each driven by Measure B when present.
- **Edge style**: `straight` (direct lines) or `curved` (quadratic
  bezier). Multi-edges between the same node pair auto-curve with
  perpendicular offset regardless of style.
- **Labels**: three modes — `show` (with configurable min-degree
  threshold), `hide`, `hover` (shows hovered node + direct neighbors,
  overrides threshold).
- **Click-to-select** on nodes with neighbor highlighting (unselected
  nodes and edges dim).
- **Cross-highlighting** via `Measure A__highlight`.
- **Per-level color overrides** (hierarchy mode) via DAX measures, same
  `isValid()` fallback pattern.
- **Tooltips** on nodes and edges.

## Fields expected

Bind these in Deneb's data well:

### Hierarchy mode (`dataMode: "hierarchy"`)

| Role | Field(s) | Required? |
|---|---|---|
| Level 1 category | One of the 4 candidate columns (via `MappedParameter` slicer) | Yes |
| Level 2 category | One of the 4 candidate columns (via `MappedParameterTwo` slicer) | Yes |
| Level 3 category | One of the 4 candidate columns (via `MappedParameterThree` slicer) | Yes |
| Node size metric | `Measure A` | Optional |
| Cross-highlight | `Measure A__highlight` (auto-generated by Deneb) | Optional |
| Edge weight metric | `Measure B` | Optional |
| Level 1 fill override | `Level1ColorOverrideFill` (DAX measure) | Optional |
| Level 1 stroke override | `Level1ColorOverrideBorder` (DAX measure) | Optional |
| Level 2 fill override | `Level2ColorOverrideFill` | Optional |
| Level 2 stroke override | `Level2ColorOverrideBorder` | Optional |
| Level 3 fill override | `Level3ColorOverrideFill` | Optional |
| Level 3 stroke override | `Level3ColorOverrideBorder` | Optional |

### Edge-list mode (`dataMode: "edgelist"`)

| Role | Field(s) | Required? |
|---|---|---|
| Source node | `Source` column | Yes |
| Target node | `Target` column | Yes |
| Edge weight | `Measure B` | Optional |

## Field mapping

Hierarchy mode uses the same 3-way exclusion cascade as sunburst, circle
packing, and dendrogram. Each level picks the first valid candidate
column not already claimed by a higher-priority level.

Edge-list mode maps `Source` and `Target` columns directly — no field
parameters needed.

## Params reference

|---|---|---|---|

## Setup in Deneb

1. Create a new Deneb visual. **Set Provider to Vega** (not Vega-Lite).
2. Paste `network.vg.json` into the Specification tab.
3. Leave the Config tab empty (the spec is self-contained).
4. Bind the candidate columns and measures in the data well.
5. For hierarchy mode: add field parameter slicers for
   `MappedParameter`, `MappedParameterTwo`, and `MappedParameterThree`.
6. For edge-list mode: bind `Source` and `Target` columns directly.

## Force presets

| Preset | Link Distance | Repulsion | Link Strength | Effect |
|---|---|---|---|---|
| `compact` | 30 | -30 | 0.3 | Tight clusters, short links |
| `balanced` | 50 | -60 | 0.1 | Default spacing |
| `spread` | 80 | -100 | 0.05 | Spacious, long links |

Override any individual parameter with `linkDistanceOverride`,
`nbodyStrengthOverride`, or `linkStrengthOverride` (set to a number to
override, `null` to use the preset value).

## Design source

D3's force simulation (`d3.forceSimulation`) maps directly to Vega's
`force` transform. The four layout algorithms correspond to common
network visualization patterns: force-directed (Fruchterman-Reingold
family), circular (nodes on a ring), grid (matrix layout), and
hierarchical (tree layout via Vega's `tree` transform).

## Known limitations

- Hierarchical layout requires hierarchy `dataMode` — in edge-list mode
  it falls back to force-directed (an arbitrary graph is not a tree).
- Draggable nodes are experimental — Power BI's own mouse event handling
  may interfere with drag in some contexts.
- Edge-list mode derives node metrics from edge weight sums (total
  incident edge weight); if Measure A is bound, it applies to hierarchy
  mode only.
- Self-loops are filtered out — edges where Source equals Target are
  excluded.
- Not yet verified in live Power BI. Deneb's field exposure quirks, real
  report theme integration, and actual Format-pane behavior need the
  report author's own live test to confirm.
- Click-to-filter (Deneb's own Power BI cross-filter integration) is
  presumed functional but not tested.
